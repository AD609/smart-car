## 一、供电与烧录

### 1.1 ST-Link 带不动电机
**现象**：烧录后电机不转，换电池供电就正常。
**根因**：ST-Link 的 3.3V 脚只能输出约 100mA，电机启动瞬间电流远超此值，电压被拉垮。
**正确做法**：TB6612 的 VM 必须用独立电池组供电，ST-Link 只负责下载和给 MCU 供电。
【已总结】

### 1.2 为什么江协科技用烧录器就能带动电机
**根因**：教程用的是 5V 脚（USB VBUS 直通，约 500mA），且是单电机空载、架空短时测试，不是带负载跑车。
**结论**：能转 ≠ 能带负载，别照搬。
【已总结】

### 1.3 烧录失败：Flash Download failed - Target DLL has been cancelled
**现象**：`flash_log.txt` 里出现该提示，下载中断。
**排查顺序**：
1. 上一次调试进 Debug 模式后没退出，Keil 还占着调试器 → 先 Stop/Ctrl+F5 退出调试
2. ST-Link 的 SWDIO/SWCLK/GND 没接好或接触不良
3. 目标板没上电（B0/B1 启动脚接错、电池没开）
4. Options → Debug → Settings 里 Flash Download 算法没选对型号
5. 芯片被读保护 → 需要先解除保护再下载

### 1.4 改了代码却没反应 —— 其实根本没编译成功
**现象**：反复修改，烧录后现象不变，像是"代码没生效"。
**根因**：链接报错（见 4.1），`Target not created`，`.axf` 没重新生成，烧进去的还是**上一次成功的旧固件**。
**正确做法**：每次烧录前必须确认编译窗口是 `0 Error(s)` 且真的生成了 axf。看到 `Target not created` 就说明这次修改完全没进芯片。

## 二、PWM 与电机驱动

- **忘开 TIM3 时钟** → PWM 无输出。用哪个定时器，就要先 `RCC_APB1PeriphClockCmd` 开它的时钟。【已总结】
- **只初始化不外调** → main 的 `while(1)` 是空的 / 没调用电机函数，自然不动。【已总结】
- **方向脚同高同低** → TB6612 两脚同时为 1 是刹车，同时为 0 是滑行，都不会转。必须一高一低。【已总结】
- **启动死区** → 0~20 不转、30 才起步，属于静摩擦 + H 桥压降，不是代码问题。【已总结】
- **PWM 取值范围** → ARR=100-1，CCR 只能 0~100；有效区约 30~100。【已总结】
- **OCxPE 预装载必须先使能并置 UG** → 否则第一周期波形异常。【已总结】
- **重复调用 `PWM_Init()` 会把 CCR 全清零** → 初始化顺序不能让后调用的函数覆盖前一个外设配置。【已总结】
- **跨函数操作对方引脚** → 左轮函数只碰 PB5/PB6 + CH2，右轮函数只碰 PB7/PB8 + CH1。【已总结】

### 2.1 左轮方向与推断相反（实测）
**现象**：`Motor_Differential` 一跑，左边电机往后转。
**根因**：左轮**前进**实际是 PB5=1、PB6=0，与之前按"IN1 在前"推断的 PB6=1 相反。
**正确做法**：
| | 前进 | 后退 | 刹车 |
|---|---|---|---|
| 左轮 | PB5=1, PB6=0 | PB5=0, PB6=1 | 两脚置 1 |
| 右轮 | PB7=1, PB8=0 | PB7=0, PB8=1 | 两脚置 1 |
**教训**：方向脚极性只能靠实测确定，不能靠推导。以后每加一个电机，都先用单独的正转测试确认。

### 2.2 差速函数只有声明没有实现
**现象**：编译通过不了，`main.c` 里调用 `Motor_Differential` 报未定义。
**根因**：函数实现被整段删掉，`Motor.h` 里还留着声明，主函数还在调用。
**正确做法**：声明和实现必须成对出现；删实现时要么一起删声明和调用，要么补回实现。
【已总结·与 4.1 同源】

### 2.3 PWM 函数命名与实际通道对不上
**现象**：看名字选函数，结果动的是另一边轮子。
**根因**：`PWM_Compare1_L` 名字说"左"，实际是 TIM3_CH1 → PA6 → **右轮**；`PWM_Compare2_R` 则是左轮。
**正确做法**：按**通道号**命名（`PWM_SetCompare_CH1` / `PWM_SetCompare_CH2`），再在注释里写清它对应哪只轮子。名字带方位最容易骗自己。

### 2.4 缺 0 速分支
**现象**：`Speed > 0` 有分支，`Speed == 0` 没处理，传 0 时电机状态不确定。
**正确做法**：三分支齐全 —— 正转 / 反转 / 停下（停下时置 `CCR = 0`，方向脚可置 1,1 刹车或 0,0 滑行，二者选一但要在注释里写明白）。
【已总结·else 分支写法讲过】

## 三、舵机

- **TIM2 频率算错** → ARR=2000-1 时是 500Hz，舵机要 50Hz，应为 ARR=20000-1（PSC=72-1）。【已总结】
- **通道写错** → 只初始化了 CH1，却往 CH3 写比较值，等于没输出。【已总结】
- **`Servo_Init` 里又调了一次 `PWM_Init`** → 把电机 PWM 清零。【已总结】

## 四、编译与工具链

### 4.1 L6218E: Undefined symbol ... (referred from main.o)
**含义**：链接阶段找不到某个函数的实体——通常是有声明、有调用，但没有实现（或 `.c` 没加进工程组）。
**这次具体原因**：`Motor_Differential` 的实现被删。
**排查顺序**：① 该 `.c` 是否已 Add 到 Keil 的 Group ② 函数名拼写是否和声明一致 ③ 实现是否被注释/删除。

### 4.2 "Target not created" 是什么意思
**含义**：编译或链接有错，Keil 没有生成目标文件。**不是烧录问题，是构建失败**。此时点下载，下的还是旧文件（对应 1.4）。

## 五、蓝牙与上位机

- JDY-31 是 SPP 经典蓝牙，配对后映射 **COM6**，9600 8N1；COM7 是本机入站口不要选。【已总结】
- JDY-31 的 AT 指令**只在未连接状态生效**，透传时发 AT 没回包是正常的。【已总结】
- COM6 打不开报 `WinError 121` → 模块被手机 APP 占着或没上电（SPP 只允许一个连接）。【已总结】
- 网页服务 8080 被系统占用 → 改用 **8090**。【已总结】
- 本机 pip 无网络 → 串口改用 `ctypes` 直连 Win32 API，零第三方依赖。【已总结】

## 七、超声波模块（HC-SR04）

### 7.1 上传的"规格书"其实是英文教程
**现象**：文件名写着"规格书"，打开是 *Complete Guide for Ultrasonic Sensor HC-SR04 with Arduino*，讲接线和 Arduino 代码，**没有电气参数表**。
**处理**：另找中文版《超声波测距模块（HC-SR04）用户手册 V2.0》（5 页），已入库到 `智能小车资料/2.传感器手册/`。

### 7.2 接线前必须确认的三点（预防）
1. Trig 是**输出**、Echo 是**输入**，Trig 平时保持低电平。
2. Echo 要配**下拉输入**，否则引脚悬空会误判边沿。
3. 两次触发间隔 **≥60ms**，否则上一次的余波会干扰下一次，表现为读数忽大忽小。

### 7.3 中文手册关键参数（V2.0 P2/P4）
- 工作电压 5V，静态电流 <2mA
- 探测距离 2cm–450cm（R3=392，出厂默认）；R3=472 时 2cm–700cm
- 感应角度 ≤15°（R3=392）
- 精度 0.3cm，盲区 2cm
- 距离 =（Echo 高电平时间 × 340m/s）÷ 2
